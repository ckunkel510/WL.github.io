# Compact UPS shipping choices

Candidate only; not released. This change is separate from PR133's optional asset mirror.

Customers currently have to discover UPS service choices under “When → Change.” The compact form now names this row “UPS shipping speed” with a “Change speed” action. Its native service dropdown includes the available service prices. Selecting a different speed previews that service's carrier estimate. Applying it invalidates the old review and requires the existing explicit review of recalculated shipping, tax and total. Native service selection, recalculation, price matching, payment and final order safeguards remain authoritative.

The UPS Rating API supports requesting rates and transit details together with `Shoptimeintransit` and `DeliveryTimeInformation`. The candidate normally uses that request instead of adding an ETA request. Transit lookup uses the ZIP’s postal city because UPS rejects city/ZIP mismatches that ordinary rating accepts; the customer’s order address is unchanged. An explicit carrier validation rejection falls back once to ordinary Shop rates within the original shared nine-second budget. Timeouts, authentication errors, rate limits and outages are not replayed. Surcharge variants sharing one native service code are reduced to the lowest-priced base service, avoiding ambiguous duplicate choices. It retains each service's business days, valid estimated arrival date and carrier pickup date. The date shown is conditional on that pickup date, never a confirmed Woodson dispatch promise. If only transit days are supplied, the form shows those days after dispatch plus store processing time. Missing or malformed estimates leave the rate usable and display that an arrival estimate is unavailable. No service-name heuristics invent dates. A restored expedited selection waits for fresh native service options instead of briefly borrowing Ground’s date.

Source: [UPS Rating API schema](https://github.com/UPS-API/api-documentation/blob/main/Rating.yaml), `Shipment_DeliveryTimeInformation`, `DeliveryTimeInformation_Pickup`, `RatedShipment_TimeInTransit`, and `ServiceSummary_EstimatedArrival`.

The native checkout has no verified UPS dispatch-date scheduling mechanism. This release does not add a dispatch-date picker. A requested later dispatch date needs a supported store workflow before it can be offered as a fulfilled order instruction.

Validation: all 634 tests pass. Server normalization and missing-estimate cases; one carrier rating call with combined transit request; trusted packing and pricing through compact response; selected-service estimate and existing price guards; native service change settles before continuation. Isolated browser preview uses the actual compact editor, summary updater, draft invalidation and CSS with synthetic quotes. Desktop 1280×900, tablet 768×1024 and phone 390×844 show no horizontal overflow, and Apply remains visible. Ground → Second Day changes the preview date; Apply clears the old total and shows Review updated total. No browser warnings/errors, order submission, cart mutation or payment information in this preview.

Before release: verify the combined UPS request against the configured live carrier account in a preview deployment, then verify a native compact speed change and refreshed total without ordering. Production publication requires approval under AGENTS.md. The root loader's versioned URL is updated in the staged admin snippet only; no WebTrack admin configuration was changed.
