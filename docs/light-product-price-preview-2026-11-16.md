# Product-page light sale price preview

Eligible light product pages now show a server-calculated sale unit price, the exact item total, the selected quantity and the eligible boxes already in the current cart. Different styles combine; existing boxes of the same SKU merge with the selected quantity. The preview describes the basket after adding the selection and performs no cart mutation.

`LightSaleDetails.js` reads the current native product quantity and price, fetches `/ShoppingCart.aspx` with same-origin credentials and no cache, and posts only eligible light lines and the selection to `/api/cart-pricing` with `action:product-preview`. It uses the existing native row contract and accepts an empty basket only when the native page explicitly says it is empty. Login redirects, missing prices and failed reads restore the native price and show a retry action. No cart contents are cached in local/session storage.

The API merges the selection, verifies current catalog data and invokes the same `priceCart` function used by cart and checkout. Basket-wide savings and integer-cent allocation remain identical. The unit price is labeled as an average when rounding is needed; the exact total is displayed alongside it. If the same SKU is already in the cart, the item total explicitly covers both its existing and selected boxes. Regular price comes from the trusted catalog. Employee views retain native pricing.

Updates cover typed quantities, native +/- button clicks (which do not emit input/change), product price/row replacement, focus, visibility return, Back/forward and native partial updates. Requests are debounced and aborted/superseded when the selection changes. Unchanged startup callbacks cannot invalidate a pending response. A fresh cart is read for each accepted selection update.

The public action returns a preview, never a native adjustment receipt. Existing reserve, fulfillment, checkout/payment, native add-to-cart controls and BisTrack promotions are unchanged. No dependencies, environment or credential changes. The current MERRY100/$100 shipping offer from PR175 is retained.

Validation: 936 automated checks pass, including 13 product-preview regressions for boundaries, mixed styles, same-SKU merging, exact cents, accessories, prior discounts, invalid input, stale catalog, employee exclusion, response supersession and native cart parsing parity. Local browser QA executes the production UI module and pricing service with synthetic native baskets: 3 other boxes +1 selected =40%/$12.00 selected; +2 selected =$23.99; +6 selected =60%/$47.97 selected. Same-SKU 3+1 =4/$47.98. Existing +/- clicks update the result. A failed native-cart read shows retry and preserves the native price. Live checks follow production publication, without payment or order submission.
