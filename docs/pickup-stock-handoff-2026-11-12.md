# Preserve pickup instructions at the native stock postback

WebTrack rebuilds the details form before confirming a branch-stock shortage. Its asynchronous pickup panel can replace the validated native notes before the native Yes postback. The modal may not be active yet when the panel first initializes, so an activation-based write guard is insufficient.

Checkout2 now keeps the server-returned pickup request in memory before initializing the date UI. A deliberate, validated Continue captures the latest edited request as well, covering same-document WebForms updates. Immediately before the existing clearance-aware stock handler clicks native Yes, it restores that exact request to the current native textarea and protects it from late UI writes until the queued postback serializes the form. Replacement textareas are resolved by ID at the restore boundary. Normal edits remain editable, other fulfillment methods and unverified/legacy text are not promoted, and compact checkout retains its existing path. No additional browser storage, account data, network request, dependency, inventory policy, date rule, payment behavior or order-submission behavior is added.

Eight regression tests cover initial async replacement before modal activation, deliberate Continue capturing new edits, ordinary editing, textarea replacement, other methods and invalid prefixes, exact restore-before-Yes ordering, missing confirmation controls and compact isolation. All 811 tests pass. The source-only trial verifies normal editing, allocation and the exact submitted request, but its native document POST stalls before sending in the local override setup. Final end-to-end validation therefore requires a clean published session; do not claim the candidate final review passed. No Complete Order or payment is authorized or submitted.
