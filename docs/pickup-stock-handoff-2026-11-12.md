# Preserve pickup instructions through native stock confirmation

The final production review of PR146 exposed a WebTrack boundary missed by the initial details-to-payment test. Native Continue returns a stock confirmation on a newly rendered details form. The pickup panel initializes asynchronously on that form and overwrote the already validated native instructions with its loading text before the existing stock handler posted Yes. Final review therefore lost the requested partial-pickup scope, time window and item allocations.

Checkout2 now preserves the native `PICKUP REQUEST at …` instructions only while a real pickup shortage confirmation is active: pickup selected, native Yes control, shortage cells, and an active Bootstrap modal or the existing handler's bypass marker. An inactive stock-modal template remains editable, so changing date, time, acknowledgement and whole/partial choice still updates notes normally. The existing clearance-aware companywide stock lookup and native Yes postback are unchanged. No payment, order submission, allocation, inventory policy or date floor changes.

Four new regressions cover exact preservation, inactive/empty modal markup and other methods, repeated asynchronous initialization without saving bad state, and ordinary editable pickup instructions. All 807 tests pass. A source-only live test uses the actual public PickupAvailability asset and overrides only Checkout2. The full 12-unit partial request was verified before native Continue, then compared verbatim after native stock confirmation, shipping, existing saved-payment selection and final review. Exact text, local/transfer/supplier allocations, first-pickup-only scope, requested date/time and remaining-pickup request all survive; loading text is absent. The test stops before Complete Order. No order, payment, card entry, token creation, saved-card edit or cart quantity change is submitted.
