# Employee customer drawer workshop — November 13, 2026

The native employee status block can be taller than its fixed utility bar. The workshop replaces its presentation with a compact Customer chip and a right-side drawer. The selected customer's name remains in the bar; the drawer shows the full name/code, available account figures, address/contact details, sales representative, and permitted native account links.

The source is `EmployeeCustomerPanel.js`. The shared `headermodern.js` loads it only on top-level WebTrack pages with the native employee-status block. The isolated preview is `test/employee-customer-preview.html`; it exercises the actual shared-header presentation with synthetic accounts. The preview's Change Customer handler is deliberately simulated and cannot open the live picker.

The customer summary comes from an authenticated, uncached, same-origin GET of `AccountInfo_R.aspx` when opened or refreshed. It uses the selected customer record, not the employee's Account Settings/profile. The current native customer code, returned employee-status customer code, and returned account-heading code must agree before rendering. It copies only an explicit field whitelist, preserves displayed zero amounts, performs no financial calculations, and does not fabricate figures for cash accounts.

An in-flight response is cancelled on close/customer change, and mismatched server context fails closed. Closing or changing tabs clears the account details. No customer information enters local/session storage, analytics, console logs, third-party requests, or repository fixtures. Native server permissions remain authoritative.

Change Customer retains the existing anchor node and handler inside the original form, with no duplicate postback. Other account links are whitelisted same-origin paths present in the native response. The drawer supports Escape, focus containment/return, backdrop dismissal, internal scrolling, and phone safe-area spacing.

The original workshop passed sixteen browser checks at four Chrome and four Mac Safari responsive sizes. The release candidate passes eighteen checks at four Chrome sizes (320×667, 390×844, 820×1180, 1280×900) and Mac Safari at 822×860, now including page-cache close/clear and restored customer-context observation. The complete Node suite passes 864 tests, including employee-only loader guards. No physical iPhone or iPad verification was performed.

The user approved publishing and live testing this employee tool on November 13. Before release, the native Chrome customer control opened WebTrack's real Search Customers screen; Cancel returned without changing the selected customer. Post-publication verification checks account parsing, native picker/cancel, account navigation, and selected-customer preservation in both live manager sessions. No payment, order, or account-record mutation belongs to this release.

Potential next steps: keep a customer workspace centered on the native selected-customer code; add permission-aware shortcuts to existing invoice, statement, quote, order, contact, and job pages. For AR, first map WebTrack's supported on-account payment flow and whether employee managers can use it for the selected customer. Any future payment screen should show the customer, invoices, and amount explicitly and leave card entry/processing with the supported payment provider and native confirmation. CRM notes, follow-up tasks, and history need an authenticated server-side store with employee attribution and account-level access checks; this drawer's in-memory summary is not a durable CRM record. No new payment or CRM persistence is implemented here.
